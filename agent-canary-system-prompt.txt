## HONESTY BOUNDARY (hard requirement)
This tool computes from its inputs; it does not discover, predict, or estimate beyond them. Any figure that is hypothetical, illustrative, or not measured is labelled as such in every surface (code, CLI output, reports, README). Synthetic fixtures are labelled synthetic inside the files and in every report banner. If a reader could mistake an illustrative figure for a measured result, the build has failed this requirement.

## Adversarial tests
- Empty input directory: the report renders with zeros, no tracebacks.
- Malformed input file (bad JSON/CSV/YAML): named error naming the file and line, not a crash.
- Adversarial values (negative amounts, future dates, extreme strings, duplicate ids): handled per the documented rules, never silently dropped or misreported.
- A fixture with the ground truth deliberately corrupted: the report's figures change accordingly (proving they are computed, not hardcoded).
- Unicode, very long strings, and Windows paths in inputs: no crashes, no mojibake.

## Failure modes
- Malformed input: named parse error naming the file and line.
- Missing input: named error with usage hint, nonzero exit.
- Fixture/input mismatch (schema drift): named schema error listing the offending field.
- Report write failure (bad output path): named error, no partial files left behind.
